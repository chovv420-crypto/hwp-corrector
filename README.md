# 한글 문서 오탈자·문맥 교정 도우미

인터넷 연결 없이, 내 PC의 특정 폴더(`my_knowledge_base`)에 있는 과거 보고서/용어집을
기준으로 아래한글(HWP·HWPX) 문서의 **오탈자·문맥·문체(어투)**를 검사하고, **원본 한글
편집창을 실제로 띄운 상태에서** 교정 진행 상황을 보여주는 별도 팝업창으로 승인 여부를
정해가며 수정하는 프로그램입니다.

- **오탈자/전문용어 검사**: 참조 폴더 문서에 없는 단어를 참조 사전과 비교해 가장
  비슷한 단어를 제안합니다. 3글자 이상 단어는 짧을수록 유사도 커트라인을 낮춰서
  이름 같은 짧은 단어의 오탈자도 잡아내지만, 그만큼 오탐 위험도 커집니다. 2글자
  단어는 퍼지 비교 대상에서 아예 제외했습니다(테스트해보니 우연히 비슷한 무관한
  2글자 단어 오탐이 너무 많았습니다) — 2글자 단어의 오탈자를 잡고 싶으면 "학습"
  기능을 쓰세요.
- **조사 받침 규칙 검사**: "책가"(→책이), "학교을"(→학교를)처럼 이/가·을/를·은/는·
  과/와·으로/로를 받침 규칙에 안 맞게 쓴 경우를 잡습니다. 참조 폴더와 무관하게
  한글 맞춤법 규칙만으로 100% 결정적으로 판정합니다(사전·AI 불필요).
- **문체 일관성 검사**: 참조 폴더 문서들이 주로 어떤 문체(합쇼체/해요체/평서체/
  반말·구어체/개조식[~함,~됨,~임,~음])를 쓰는지 자동으로 파악하고, 검사할 문서에서 그 문체와 다른 문장을
  찾아 표시합니다. 단, 어미를 자동으로 바꿔 쓰지는 않습니다(잘못 바꾸면 오히려
  어색해질 수 있어서) — 대신 팝업창에 원래 문장이 채워진 입력창을 보여주고,
  필요하면 직접 고쳐서 "이 문장 반영"에 체크하면 그 문장으로 실제 문서에 반영됩니다.
- **학습 기능("직접 알려주기")**: 자동 검사기가 놓친 오류를 팝업창에서 직접
  "틀린 표현 / 올바른 표현 / 이유"로 입력하면, 그 자리에서 실제 문서에도 반영되고
  `my_knowledge_base/_learned_corrections.json`에 저장됩니다. 다음 실행부터는
  그 표현이 다시 나오면(정확히 일치할 때) 유사도 계산 없이 곧바로 잡아내고, 올바른
  표현이 참조 사전 어휘에도 더해져 비슷한 다른 오탈자를 잡는 데도 도움이 됩니다.
  즉, 쓸수록 그 조직 문서에 맞게 똑똑해집니다.
- **흔한 맞춤법 오타 검사**: "됬어요"(→됐어요), "몇일"(→며칠), "웬지"(→왠지),
  "하개"(→하게)처럼 표준 맞춤법에 아예 없는, 늘 틀린 것으로 볼 수 있는 표현을
  잡습니다. "않"이 "~지 않다" 구성이 아닌데 쓰인 경우("않됩니다"→안됩니다)도
  같은 원리로 잡습니다. 참조 폴더와 무관하게 항상 적용됩니다.
- **마침표 누락 확인**: 마침표/물음표/느낌표 없이 끝나는, 제목·항목이 아닌 것으로
  보이는 문장을 표시합니다(문체 확인과 같은 칸에 나옵니다).

## ⚠️ 실행 환경 (중요)

이 프로그램은 `pyhwpx`로 **실제 한컴오피스 '한글' 프로그램을 화면에 띄워 원격 조종**합니다.
따라서 반드시 아래 조건이 필요합니다.

- **Windows** (macOS/Linux에서는 한글 창을 띄울 수 없어 동작하지 않습니다)
- **한컴오피스(아래한글)** 설치 — 이건 실행 파일(.exe)로 만들어도 피할 수 없습니다
- Python 3.9 이상 — **단, [실행 파일(.exe)로 만들면](#실행-파일exe로-만들기--파이썬-설치-없이-쓰기)
  최초 빌드할 때 1번만 필요하고, 그 이후 exe를 실행하는 PC들에는 파이썬이 없어도 됩니다.**

개발은 Mac에서 했지만, 실제 실행/테스트는 한글이 설치된 Windows PC에서 해야 합니다.

## 설치 (Windows PC에서, 파이썬으로 바로 실행할 경우)

```bash
pip install -r requirements.txt
```

- `pyhwpx`: 실제 한글 프로그램을 원격 조종하는 라이브러리 (Windows 전용)
- `konlpy`: 조사/어미를 떼고 명사만 비교하기 위한 형태소 분석기. **Java(JDK) 설치가
  필요**하며, **정식 사용 시에는 설치를 강력히 권장**합니다. konlpy가 없으면 자동으로
  "한글 어절에서 조사만 간단히 떼어내는" 대체 방식으로 동작하는데, 이 대체 방식은
  "배포했습니다" ↔ "배포했다"처럼 **문장 어미(문체) 차이를 오탈자로 잘못 제안**하는
  경우가 있을 수 있습니다. konlpy가 설치되어 있으면 명사만 정확히 비교하므로 이런
  오탐이 크게 줄어듭니다.

## 실행 파일(.exe)로 만들기 — 파이썬 설치 없이 쓰기

**이 항목은 최초 1번, "실행 파일을 만드는 사람"만 하면 됩니다.** 그 결과로 나오는
`HwpCorrector.exe` 파일은 그 이후로 **파이썬 설치 없이** 바로 실행됩니다(단, 한컴오피스는
exe를 실행하는 PC마다 반드시 설치되어 있어야 합니다 — 이건 프로그램 특성상 피할 수 없습니다).

1. Windows + 한컴오피스가 설치된 PC에 파이썬을 설치합니다 (최초 1회만, 빌드용).
   [python.org](https://www.python.org/downloads/)에서 받으면 됩니다.
2. 이 폴더의 `build_windows.bat` 파일을 더블클릭합니다.
3. 몇 분 기다리면 `dist` 폴더 안에 `HwpCorrector.exe`가 생성됩니다.
4. 이 exe 파일을 원하는 위치로 옮기고(USB나 다른 PC에 복사해도 됨), 같은 폴더에
   `my_knowledge_base` 폴더를 만들어 참조 문서를 넣어두면 됩니다.
5. 이후로는 `HwpCorrector.exe`를 더블클릭하기만 하면 됩니다 — 파일 선택 창이 뜨고,
   나머지는 아래 "사용 방법"과 동일합니다.

빌드에 문제가 생기면(예: pyhwpx 관련 DLL을 못 찾는다는 오류), `build_windows.bat`
안의 `pyinstaller` 명령을 상황에 맞게 조정해야 할 수도 있습니다.

## 사용 방법

exe 파일로 실행하는 경우 1번(파이썬 설치)은 필요 없습니다.

1. `my_knowledge_base` 폴더에 우리 조직에서 쓰는 올바른 표현이 담긴 과거 보고서나
   용어집(`.hwpx`, `.hwp`, `.txt`)을 넣어둡니다. 이 폴더의 문서들이 "정답 사전"이 됩니다.
2. 아래 명령으로 검사할 문서를 지정해 실행합니다 (exe라면 그냥 더블클릭해도 됩니다 —
   인자 없이 실행하면 파일 선택 창이 뜹니다).

```bash
python main.py 검사할문서.hwpx
```

exe로 실행할 때는 명령 프롬프트에서 다음처럼 써도 됩니다.

```bash
HwpCorrector.exe 검사할문서.hwpx
```

옵션:

```bash
python main.py 검사할문서.hwpx -r ./my_knowledge_base -o 결과파일.hwpx
```

- `-r, --reference`: 참조 폴더 경로 (기본값 `./my_knowledge_base`)
- `-o, --output`: 저장할 파일 경로 (기본값: `원본이름_교정본.확장자`)

실행하면:

1. 콘솔에 참조 폴더 분석 진행률이 출력됩니다.
2. **실제 아래한글 창**이 화면에 뜨고, 검사할 문서가 열립니다.
3. 그 옆에 **"교정 도우미" 팝업창**이 함께 뜹니다. 문단을 하나씩 훑으면서, 참조
   사전에 없는(오탈자로 의심되는) 단어를 노란색으로 표시합니다.
4. 노란 단어를 클릭하면 하단에 **왜 이 단어를 의심하는지(참조 문서 출처, 등장 횟수,
   글자 유사도)**가 표시되고, "이 단어 승인 / 이 단어 거절" 버튼이 활성화됩니다.
5. 그 문단에 참조 문서와 다른 문체(어투)의 문장이 있으면 "문체 확인 필요 문장" 칸에
   따로 표시됩니다. 필요하면 입력창의 문장을 직접 고친 뒤 "이 문장 반영"에 체크하세요.
6. 자동 검사기가 놓친 오류를 발견했다면, "자동으로 못 잡은 오류를 발견했나요?" 칸에
   틀린 표현/올바른 표현/이유(선택)를 입력하고 "학습하고 지금 문서에 반영"을 누르세요.
   현재 보고 있는 문단 여부와 상관없이 즉시 문서에 반영되고, 다음 실행부터는 자동으로
   잡아냅니다. 같은 문단을 보면서 여러 번 입력해도 됩니다.
7. "다음 문단 →" 버튼을 누르면, 승인한 단어와 체크한 문체 수정 문장이 **실제 한글
   창에서 찾아 바꾸기가 실행되는 모습을 그대로 볼 수 있습니다.** (원본 창 + 팝업창을
   나란히 띄워두고 지켜보면서 진행하는 그 방식입니다.)
8. "여기서 중단하고 저장"을 누르면 그때까지 승인한 내용만 반영한 뒤 저장하고 종료합니다.
9. 끝까지 진행하면 자동으로 `-o`로 지정한(또는 기본) 경로에 저장되고, **소요 시간
   내역**(문서 스캔/자동 계산/실제 반영/저장/검토 대기 시간 각각)이 팝업으로 표시됩니다.

## 동작 원리

- **참조 사전 구축** (`hwp_corrector/reference_db.py`): 참조 폴더의 문서에서 명사를
  추출해 단어별 등장 빈도와 출처 파일명을 기록합니다.
- **교정 제안** (`hwp_corrector/matcher.py`): 검사할 문서를 어절 단위로 쪼개, 참조
  사전에 없는 단어를 `difflib`로 사전 안의 가장 비슷한 단어와 비교합니다. 2글자
  단어는 퍼지 비교에서 제외하고, 3글자 이상만 커트라인을 다르게 적용합니다:
  3~4글자 60%, 5~6글자 68%, 7글자 이상 72%. (길이가 짧을수록 글자 1개 차이가
  유사도에 미치는 영향이 커서, 커트라인도 낮춰야 짧은 단어의 오탈자를 놓치지
  않습니다. 다만 2글자는 낮춰도 무관한 단어끼리 오탐이 너무 많아 아예 뺐습니다.)
- **조사 규칙 검사** (`hwp_corrector/josa_checker.py`): 한글 유니코드 코드포인트에서
  받침 유무를 계산해(음절 = 초성·중성·종성 조합이라 종성이 있는지로 판정), 조사가
  받침 규칙에 맞는지 검사합니다. 예외(ㄹ받침일 때 "으로"가 아닌 "로") 규칙도 반영했습니다.
- **문체 검사** (`hwp_corrector/style_checker.py`): 문장을 마침표/물음표/느낌표
  기준으로 나눠(단, "1." "가." 같은 번호 매기기는 문장 경계로 보지 않음) 종결어미로
  합쇼체/해요체/평서체/반말/개조식(~함,~됨,~임,~음)을 판정합니다. 참조 폴더 문서들의 문체 분포에서 가장
  많이 쓰인 문체를 "기준 문체"로 삼고, 다른 문체의 문장을 찾아냅니다. 번호·기호로
  시작하는 제목/항목은 문장이 아닐 가능성이 높아 판정에서 제외합니다.
- **흔한 오타·마침표 검사** (`hwp_corrector/common_typos.py`): 표준 맞춤법에 없는
  것으로 확실한 표현(됬/몇일/웬지 등)과 "~지 않다" 구성이 아닌 "않"을 문맥과
  무관하게 잡습니다. 되/돼, 로써/로서처럼 뒤에 오는 말에 따라 맞고 틀림이
  달라지는 것은 규칙만으로 신뢰성 있게 못 잡아서 넣지 않았습니다.
- **학습 사전** (`hwp_corrector/learned_corrections.py`): 사람이 입력한 교정을
  `_learned_corrections.json`에 저장합니다. 다음 실행 시 `reference_db.py`가 이를
  불러와 정확 일치 사전(`exact_corrections`)에 등록하므로, 이후에는 유사도 비교
  없이 즉시 잡힙니다(신뢰도 100%로 취급).
- **문서 제어** (`hwp_corrector/worker.py`): `pyhwpx`의 `init_scan()/get_text()`로
  문서를 문단 단위로 읽고, 승인된 교정은 `find_replace()`(찾아 바꾸기)로 실제
  한글 문서에 반영합니다. 이 과정이 화면에 그대로 보입니다. 각 단계(스캔/계산/반영/
  저장/검토 대기)의 소요 시간을 측정해 완료 시 보여줍니다.
- **팝업 UI** (`hwp_corrector/gui.py`): Tkinter로 만든 별도 창. 워커 스레드와는
  큐(Queue)로 통신하며, 문단 하나가 도착할 때마다 렌더링하고 사용자 결정을
  기다립니다.

## 소요 시간

macOS 개발 환경에는 한글 프로그램이 없어 실제로 측정하지는 못했습니다. 대신
프로그램이 **매 실행마다 자동으로 소요 시간을 측정해 완료 팝업에 보여주도록**
만들어 두었습니다 (문서 스캔 / 자동 계산 / 실제 반영 / 저장 / 검토 대기 각각).
Windows에서 처음 돌려보시면 정확한 숫자를 바로 확인할 수 있습니다.

참고로 기계적으로 처리되는 부분(스캔·계산·반영·저장)은 2페이지 분량 문서 기준으로
대략 수십 초 이내일 것으로 예상합니다(참조 폴더에 `.hwp`/`.hwpx` 파일이 많으면
그만큼 늘어남 — 파일마다 한/글로 열어야 해서). 반면 **전체 체감 시간을 가장 많이
좌우하는 건 사람이 팝업창에서 승인/거절을 검토하는 시간**인데, 이건 오탈자가 몇 건
나오느냐와 사람이 얼마나 빨리 확인하느냐에 달려 있어 제가 미리 예측할 수 없습니다.

## 알려진 제한 사항

- `.hwp`(구 바이너리 형식)보다는 `.hwpx`(개방형 XML) 형식이 서식 보존에 더 안전합니다.
- 문서 안에 완전히 동일한 어절이 여러 곳에 있으면, `find_replace(direction="AllDoc")`가
  커서 위치를 기준으로 다음 일치 항목을 바꾸는 방식이라 아주 드물게 의도와 다른
  위치가 바뀔 수 있습니다. 반영 후 결과를 한 번 훑어보는 것을 권장합니다.
- 부분 서식(굵게/밑줄 등 어절 일부에만 적용된 서식)은 찾아 바꾸기 특성상 유지되지만,
  문서 전체 서식이 복잡할 경우 예외적으로 흐트러질 수 있습니다.
- 문체 검사는 문장 끝 몇 글자만 보는 간단한 규칙 기반이라, 제목·항목 나열처럼 짧고
  어미가 없는 문장은 판정하지 않고 건너뜁니다(오탐 방지 목적). 완벽한 문법 분석은
  아니므로 최종 확인은 사람이 하는 것을 전제로 합니다. 특히 반말/구어체 판정은
  "어/아/야/지/네" 같은 흔한 종결 글자로 판단하기 때문에, 다른 문체보다 오탐
  가능성이 조금 더 있습니다.
- 개조식(~함/~됨/~임/~음)은 종결 글자로 판정하지만, "회의 진행."처럼 그 글자조차
  없이 명사로 뚝 끊기는 완전한 개조식 종결은 제목과 구분할 방법이 없어 판정하지
  않습니다.
- 학습 사전은 "정확히 똑같은 표현"에만 반응합니다. 조사가 다르게 붙거나 형태가
  조금 달라지면(예: "힝징안진부는" vs "힝징안진부에서") 핵심 단어가 같으면 잡히지만,
  아예 다른 오타(예: "힝징한진부")에는 반응하지 않습니다 — 그런 경우 또 한 번
  가르쳐주면 됩니다.
- **이 프로그램이 잡지 못하는 것**: "이/가"·"을/를" 중 문맥상 어느 쪽이 맞는지(주격/
  목적격 선택 오류), 주어-서술어 호응, **되/돼**, **로써/로서**, 띄어쓰기는 검사하지
  않습니다. 이것들은 뒤에 오는 말이나 문장의 뜻을 이해해야 판단할 수 있어서,
  사전·규칙 기반만으로는 신뢰성 있게 잡을 수 없습니다(억지로 넣으면 오탐이 크게
  늘어남). 띄어쓰기는 PyKoSpacing 같은 별도의 사전학습 모델을 추가하면 가능하지만,
  무거운 의존성(TensorFlow 등)이 필요해 이번 버전에는 포함하지 않았습니다.
